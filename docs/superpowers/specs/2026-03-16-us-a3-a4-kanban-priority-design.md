# US-A3 / US-A4 看板与优先级视图设计

日期：2026-03-16

## 背景与目标
实现用户故事 US-A3（看板视图浏览任务）与 US-A4（优先级视图切换），让用户能在一个看板中按状态查看任务，并可切换到优先级四象限视图进行决策。

## 约束与假设
- 采用前端分组/排序/筛选（方案 A）。
- 优先级分组：P0/P1/P2/P3（Eisenhower 四象限）。
- 优先级默认值：若任务缺失优先级，视图中按 P1（重要不紧急）展示。
- 简要执行状态：使用任务 `status` 的人类可读文本。
- 卡片上的工作区展示“名称”。

## 视图设计

### 1. 看板视图（状态分列）
- 列顺序固定：`Backlog / Todo / In Progress / Review / Done / Blocked`。
- 每列内排序：先优先级（P0→P3），再创建时间（新→旧）。
- 卡片显示字段：
  - 标题
  - 优先级（P0–P3 + 重要/紧急文案）
  - 标签
  - 工作区名称
  - 简要执行状态（状态文案）
- 顶部筛选：
  - 工作区下拉（单选/全部）
  - 标签下拉（多选/全部）

### 2. 优先级视图（四象限）
- 四象限固定：
  - P0：重要且紧急
  - P1：重要不紧急
  - P2：紧急不重要
  - P3：不紧急不重要
- 每象限内排序：优先级（P0→P3），再创建时间（新→旧）。
- 卡片显示与看板一致。
- 视图顶部提供切换回看板；卡片点击进入任务详情页。
- 筛选条件与看板一致，作用于四象限。

## 数据与接口
- 前端直接调用 `GET /issues` 获取列表。
- 前端执行筛选（工作区/标签）、分组（状态/优先级）、排序（优先级→创建时间）。
- `PATCH /issues/:id` 继续用于拖拽变更状态（看板内）。
- 不新增分组接口，维持 API 简洁。

## 交互与一致性
- 刷新后与数据库一致：依赖 `GET /issues` 实时数据刷新。
- 拖拽更新失败时前端回滚状态。
- 筛选条件纯前端状态，不写入后端。

## 错误处理
- 拉取失败：显示错误提示并保持当前视图布局。
- 更新失败：提示错误并恢复原状态。

## 测试要点
- 看板列顺序与状态映射正确。
- 优先级视图四象限分组正确，默认缺失优先级归入 P1。
- 排序稳定：优先级优先、创建时间次之。
- 筛选对两个视图都生效。
- 刷新后数据与数据库一致。
