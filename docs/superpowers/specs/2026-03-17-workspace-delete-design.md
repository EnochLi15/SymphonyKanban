# 工作区删除功能设计说明

## 背景与目标
在“工作区管理”列表页增加删除工作区能力，并使用 Element Plus 二次确认弹窗。若工作区下仍有任务/issue，禁止删除并提示未清理数量。

## 范围

### 覆盖
- 列表页为每个工作区卡片提供删除按钮
- 删除前进行可删除性校验，返回未清理任务数量
- 可删除时使用 Element Plus 二次确认弹窗
- 不可删除时展示提示（包含数量）

### 不覆盖
- 不在详情页提供删除入口
- 不做任务级联删除（明确禁止）

## 需求与验收标准

### 交互需求
1. 删除入口在“工作区管理”列表页，每个卡片右侧显示删除按钮
2. 点击删除时先请求后端校验接口
3. 若 `issueCount > 0`：提示“无法删除”并显示数量
4. 若 `issueCount = 0`：弹出 Element Plus 二次确认弹窗
5. 确认删除后调用删除接口，成功后刷新列表
6. 删除失败时提示错误并保留列表

### 验收标准
- 不能删除仍有任务的工作区
- 提示中显示未清理任务数量
- 可删除时必须二次确认
- 删除成功后列表更新

## API 与数据流

### 新增接口
- `GET /workspaces/:id/deletion-check`
  - 响应：`{ deletable: boolean, issueCount: number }`

### 删除接口
- `DELETE /workspaces/:id`
  - 后端需再次校验；若仍有任务，返回 `409` 并附 `issueCount`

### 前端流程
1. 点击删除 → 调用 `deletion-check`
2. `issueCount > 0` → 显示提示，终止
3. `issueCount = 0` → 弹确认框
4. 确认后调用 `DELETE` → 成功刷新列表

## UI/组件设计

### 删除按钮
- 位置：工作区卡片右侧
- 点击不触发卡片导航（阻止事件冒泡）
- 支持 loading/禁用状态（避免重复点击）

### 弹窗与提示
- 不可删除提示（Element Plus 消息或 alert）
  - 标题：无法删除工作区
  - 内容：该工作区下还有 {count} 个任务未清理，请先处理后再删除。
- 二次确认弹窗（Element Plus confirm）
  - 标题：确认删除工作区？
  - 内容：删除后将无法恢复。
  - 按钮：取消 / 删除

## 状态与逻辑
- `deletingId`：当前正在删除的工作区
- `handleDelete(workspace)`：
  - 先校验 → 再确认 → 再删除
  - 失败时提示错误且保留输入

## 风险与对策
- 风险：用户误删
  - 对策：二次确认弹窗
- 风险：并发删除或状态变化
  - 对策：后端删除接口再次校验

## 结论
在列表页提供删除按钮，通过后端校验与二次确认实现安全删除，并明确禁止删除仍有任务的工作区。
