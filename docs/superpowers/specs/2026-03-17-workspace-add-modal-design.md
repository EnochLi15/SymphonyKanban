# 工作区添加：单一模态表单设计说明

## 背景与目标
当前“工作区管理”页使用 `window.prompt` 逐个收集字段（名称、路径、上下文），交互割裂且不符合现有 Element Plus UI 风格。目标是将添加工作区改为一个 Element Plus 模态框，集中填写多个字段并进行必填校验。

## 范围

### 覆盖
- 仅修改“工作区管理”页的“添加工作区”交互
- 使用 Element Plus `ElDialog` + `ElForm` 完成字段输入与校验
- 字段必填规则：
  - 工作区名称：必填（非空）
  - 本地路径：必填（非空）
  - 上下文说明：可选

### 不覆盖
- 不新增路由页面
- 不修改后端 API 契约
- 不增加路径格式或合法性校验（仅非空校验）
- 不重构其它页面

## 需求与验收标准

### 交互需求
1. 点击“+ 添加工作区”打开模态框
2. 模态框包含三个字段：名称、路径、上下文
3. 点击“创建”时触发表单校验：名称/路径不能为空
4. 校验通过后调用创建工作区 API
5. 创建成功后关闭弹窗并刷新工作区列表
6. 创建失败时保留弹窗与用户输入，显示错误提示（Element Plus 默认提示或现有样式）
7. 点击“取消”关闭弹窗且不提交

### 验收标准
- 不再出现 `window.prompt` 交互
- 表单校验在 UI 上可见（错误提示）
- API 成功后列表更新且弹窗关闭
- API 失败后弹窗保留输入且能再次提交

## UI/组件设计

### 组件结构（概念）
- `ElDialog`
  - `ElForm`
    - `ElFormItem`: 工作区名称（`ElInput`）
    - `ElFormItem`: 本地路径（`ElInput`）
    - `ElFormItem`: 上下文说明（`ElInput`/`textarea`）
  - Footer Buttons:
    - 取消
    - 创建

### 文案（可与当前一致）
- 对话框标题：添加工作区
- 字段标签：
  - 工作区名称
  - 本地路径
  - 上下文说明（可选）
- 按钮：取消 / 创建

## 数据与状态

### 新增/调整状态
- `dialogVisible: boolean`
- `form: { name: string; localPath: string; context: string }`
- `rules`：名称与路径 `required` 校验规则
- `isSubmitting: boolean`（可选，用于按钮 loading）

### 数据流
1. 点击按钮 -> `dialogVisible = true`
2. 填写表单 -> 更新 `form`
3. 点击创建 -> `validate()` -> 调用 `api.createWorkspace()`
4. 成功 -> 关闭弹窗 + `load()`
5. 失败 -> 错误提示 + 保留 `form`

## 错误处理
- `createWorkspace` API 失败时：展示错误提示，避免清空表单
- 校验失败：阻止提交

## 测试与验证（仅前端）
- 手动验证：
  - 不填写名称或路径时点击创建，出现错误提示
  - 正常创建后列表刷新
  - 断网或 API 失败时弹窗保留输入

## 迁移与兼容
- 仅前端行为调整，无后端变更
- 不影响已有工作区数据

## 风险与对策
- 风险：用户频繁点击“创建”造成重复提交
  - 对策：提交中禁用按钮或显示 loading（可选但推荐）

## 结论
以 Element Plus `ElDialog + ElForm` 替换 `window.prompt` 收集字段，实现集中填写与必填校验，保持与现有 UI 风格一致。
